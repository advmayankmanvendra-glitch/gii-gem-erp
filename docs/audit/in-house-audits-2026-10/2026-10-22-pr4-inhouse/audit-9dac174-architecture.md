## Verdict

**Rating: Sustainable with conditions. Better than 3c12e50. No High finding. Four Medium.**

What improved:
- **C1 is closed.** `computeOrderClosure` has no default any more. It throws a guided error when no `outstandingFor` is passed (`orderClosureService.js:13`). A posted invoice with no live receivable is not counted as settled (`:22-23`). Both cases are tested.
- **A1 is closed.** The two sub-folder READMEs and `run-full.txt` are now in the manifest. The check fails on any archive file that the manifest does not list (`verify-governance-graph-registry.js:344-347`).
- **S1 is mostly closed.** `recordGrant` (`main.js:326-329`) is called by both `guarded` and `sessionGuarded`, so the `account_mapping` channels and the session-guarded `settings` channels now write their grant row. One IPC test covers `account-mapping:registry`.
- **The sessionGuarded spoofing gap is closed.** The handler now gets only `args[0]` and then the actor (`main.js:347`), so a screen can no longer add an extra argument that takes the actor's place. I checked all eight `sessionGuarded` handlers: none takes more than `(payload, actor)`. Nothing breaks.
- **P2 is closed, and P3 is narrowed.** Browser preview now shows "Simulation not available" with the reason (`ProfitSimulatorScreen.jsx:147-148`). The UI maximum now matches the service's 1000.
- **The admin audit-trail regression in 3c12e50 is fixed.** Admins hold `settings`, not `view_reports`, and they see the trail again (`seesAuditTrail`, `main.js:195-197`, tested). The same rule now covers voucher drill-down too (`:948-952`).
- **Legacy go-live runs fail closed.** A run that has neither a stored mark nor `auditIdAtStart` is refused with a guided message that points to Backup & Restore (`goLiveService.js:253-255`, tested).
- **The Tally preview no longer runs one duplicate query per master** (per-preview cache), and it has caps on masters and on spreadsheets.
- `profitSimulatorService.js` is now in `lint:syntax`.

What needs attention:
- **The manifest regenerator re-blesses edits (A2, Medium).** It recomputes every hash, and the verify failure tells people to run it.
- **Grant rows are now written for read-only screens (S2, Medium).** Opening Account Mapping writes three hash-chained rows. The quick-create ledger dialog writes one on every date change.
- **Closure now nets settlement across the whole order (C3, Medium).** This is a new rule that can disagree with the bill-wise receivables report, and it needs the owner's OK.
- **Test coverage was weakened (T2, Medium).** The 32-million shared-string budget is no longer reached by any test, and the new limits and the duplicate cache have no tests.

## Design choices asked about

| **`recordGrant` in both wrappers** (`main.js:316`, `:326-329`, `:344`) | **Right fix for the reported gap, but done at the wrong grain.** (a) It removes the duplicated insert. One function now decides whether a grant is recorded. (b) It still has two wrappers with different contracts. `guarded` stamps payloads (`withActor`), enters `runAsActor` with the full user row and spreads every argument. `sessionGuarded` passes `(args[0], { user_id, user_role })`. The fold that S1 and M2 recommended was not done. `sessionRequired` (`:354-365`) is still dead code. (c) **Reads now write grant rows (S2).** `account_mapping` covers four read channels (`:869-892`), and `auth:list-users` (`:842`) reads under `settings`. `AccountMappingReviewPanel.jsx:76-78` makes three of those calls on every load, and `QuickCreateMasterDialog.jsx:206` makes one on every `effective_from` change. Each call is a hash-chained `audit_log` row. The 3c12e50 report asked for "grants for writes only", and this change does the opposite. These rows use `table_name = "system"`, so they do not block go-live rollback (`goLiveService.js:268-273` only counts book tables). (d) **Gaps still open.** `updates:install` checks `settings` directly (`main.js:1224`) and writes no grant row. `financial_year_reopen` is in `AUDITED_GRANTS` but no channel asks for it: `financial-years:status` reopens under `financial_year_close` (`:946`). The grant row is still written before the handler runs, so a failed action leaves a "granted" row. (e) The commit message says "the session-guarded settings channels leave a permission_granted row too". That is true, but `updates:install` is a `settings` channel outside both wrappers. |
| **`firstPayload` plain-object test** (`main.js:189-191`) | **Good, and narrowly scoped.** A `Uint8Array` or other typed object is no longer spread into the permission context. IPC structured clone produces objects of the main realm, so `Object.prototype` matches as it should. A `Date` argument is no longer treated as a payload. No channel sends one first *(inferred)*. Covered by the existing byte-array test. |
| **`seesAuditTrail` and the drill-down filter** (`main.js:195-197`, `:867`, `:948-952`) | **Right outcome, wrong layer (L1 grew).** It is now a named policy, which is better than the inline check. But it is still access policy in `main.js`, applied separately to two channels, and it uses `roleCan`, a third permission idiom. `masterDataToolsService.js:577-583` and `supportBundleService.js:23` also return audit rows and are not covered by this policy *(inferred: both are admin or diagnostic paths)*. The drill-down filter has no test. **Fix:** a `canSeeAuditTrail(actor)` in `authService` (or a report-permission helper), applied inside `accountingData` and `drilldownData`, plus an IPC test for drill-down. |
| **Health snapshot actor** (`main.js:1193-1198`) | **The fix is right: the screen can no longer name the user. Not tested. **Fix:** `recordVerificationSnapshot(root, checks, context, actor)` with the lookup inside the service. Drop the camel-case aliases from what the service reads. |
| **Closure settlement** (`orderClosureService.js:11-28`; `init.js:1443-1451`; `main.js:1405`) | **One required dependency: C1 is resolved. The rule itself changed (C3).** (a) `outstandingFor` is required, and production passes `receivableOutstandingForSettlement`. Good. (b) **Netting across the order is new.** `unsettled` is empty whenever the order's total outstanding is ≤ 0.005 (`:27-28`). The aim is that a credit note booked as its own negative invoice nets against the invoice it corrects (tested, `s9`). But the rule is "any negative balance on the order offsets any positive one". One example: invoice A is paid in full and then gets a linked guided credit note, so it goes to −100. Invoice B for 100 is unpaid. The order nets to 0 and can be closed, while the bill-wise receivables report still shows B with 100 outstanding *(inferred from `:26-28` and `reportBuilders.js:244-262`)*. That is a §4 "existing workflow" decision: (nn). The owner list mentions only "counts credit notes". (c) **"As the bill-wise receivables report shows it" is not quite true** (`init.js:1443`). The report computes `r.balance_outstanding − notes` from the stored column and excludes `status = 'Reversed'` receivables (`reportBuilders.js:254-258`). The settlement function recomputes `invoice_amount − allocations − advance adjustments − notes`, and its receivable lookup does not filter on `Reversed`. Both agree only while the stored balance is in sync *(inferred)*. (d) `receivableOutstandingForSettlement` is a new export on the 2,134-line `init.js`. It calls `postedGuidedNoteAdjustments`, which loads and JSON-parses every posted credit note of the company, once per posted invoice. That is fine for one order, but it is O(invoices × notes). (e) N7 is unchanged: `markOrderOperationallyClosed(db, id, audit, closureOptions = {})` still has two optional positional parameters. A call without options now throws a guided error inside the transaction, which is correct. **Fix:** owner decision on netting. If netting is kept, net only credit-note invoices against the invoices they reference. Move the outstanding calculation into a `receivablesService` that both the report and closure call, and test that the two agree. |
| **XLSX expansion ratio** (`importParserService.js:283-284`, `:335-339`) | **A reasonable zip-bomb heuristic. It is a new class of refusal, and real files are not tested (X3).** It refuses any part over 4 MB that inflated more than 200 times. The check runs after inflation, so the decompression cost is still paid: the 64 MB `maxOutputLength` remains the real CPU bound. The heuristic's own evidence is mixed. The commit had to rewrite a test sheet ("a sheet of one repeated character is refused as a zip bomb", `audit2-regressions.test.mjs:480-483`), so a structurally valid sheet was refused. Machine-generated exports with long runs of empty styled cells or padded text can compress very well *(inferred; no real-workbook fixture tested)*. The message says "save again from Excel". That will not help a genuinely repetitive sheet, but the "or as CSV" route will. **Fix:** add a fixture of a real, sparse, styled export to the tests. Consider applying the ratio only to `sharedStrings.xml`, or only above a higher absolute size. List it for the owner as (pp). |
| **Tally preview duplicate cache** (`importValidationService.js:63-125`; `tallyImportService.js:438-443`, `:485-542`) | **Correct, and it fixes a real N×table scan. It adds a second implementation of every lookup and mutable state in the factory.** (a) The keys are built by SQLite's `LOWER(TRIM(COALESCE(...)))` on both paths, and `ORDER BY id` keeps the first match, so the results match the uncached `LIMIT 1` *(the uncached query has no ORDER BY, but rowid order is the usual result)*. (b) **Two code paths per master kind** (`byText`, `byCompanyText`, items). Every future rule change has to be made twice, and `warehouses` (`:123-131`) is cached in neither. (c) The generic master-import preview still calls without a cache (`importValidationService.js:377`), so the per-row scan this fixes for Tally remains there. (d) `previewDuplicateCache` is a `let` in the factory closure, set and cleared around one synchronous preview (`tallyImportService.js:487`, `:541`). It is safe today because the preview is synchronous. If the preview ever awaits (for example a worker-thread parse), it becomes shared mutable state across calls. **Fix:** make `findMasterImportDuplicate` always take a cache, with a new `Map` per call when none is given. Then there is one code path. Pass the cache as an argument through `tallyLedgerCandidate` and the other candidate builders, not through the closure. |
| **Tally masters and spreadsheet caps** (`tallyImportService.js:442-443`, `:510-528`, `:535`) | **Sensible limits, with uneven failure modes and one wasted scan.** (a) `tallyTagBlocks(xmlText, "STOCKITEM")` scans the whole file only to count. `parseTallyStockItemsXml` then scans it again (`:519`). Count from `stockPreview.items.length` after parsing, or pass the blocks on. (b) The masters cap aborts the whole preview through a typed code, but the spreadsheet cap marks only that file as failed ("Skipped: …"). Both are defensible, but the reasons are not recorded. (c) The locale is mixed again: the masters message uses `toLocaleString("en-IN")` ("1,00,000"), while the parser's messages use western grouping. (d) Neither cap is tested. |
| **Audit-archive manifest script** (`scripts/update-audit-manifest.js`; `verify-governance-graph-registry.js:14`, `:344-347`) | **It closes A1, but the regenerator weakens the protection it maintains (A2).** (a) **It re-blesses edits.** The script hashes every file again and overwrites the manifest (`:42-52`). It has no notion of "existing entry". The README calls a report "never edited after it is added", but the workflow is now: edit an old report, add a new one, run the script that the verify failure names (`verify-governance-graph-registry.js:347`), and both checks pass. Only a reviewer reading the manifest diff would see a changed hash. (b) **Coupling.** The verify script imports from a script that writes files. The `process.argv[1]` guard keeps it from running, but a lint or graph tool that loads all scripts would now load a writer. `archiveFiles` belongs in `scripts/lib/`. (c) It depends on `readdirSync({ recursive: true, withFileTypes: true })` and `parentPath ?? path`, which need Node ≥ 20.1. The repo has no `engines` field. Node 22 (local) and Electron 37 are fine. On an older Node, `recursive` is ignored, so sub-folder files would be treated as unlisted. That fails loudly, not silently. (d) Symbolic links are skipped by `isFile()` with no message *(Info)*. (e) There is no npm script and no `lint:syntax` entry for the new script. There is no test that the archive check fails on an unlisted or edited file. Keep existing entries, add new paths, and refuse (exit 1, naming the files) when an existing entry's size or hash differs, unless `--accept-changed <path>` is given. Move `archiveFiles` to `scripts/lib/auditArchive.js`. Add a small test with a temporary folder: an unlisted file fails, an edited file fails, and regeneration refuses an edit. |
